### Этап 4. Разработка ETL/ELT-процесса

Задачи:
1.	Реализация трансформаций на Spark:
  -	Агрегация данных.
  -	Инженерия признаков для ML-модели (не менее 5 признаков).
  -	Преобразование данных в формат, готовый для загрузки в хранилища.
2.	Загрузка данных в целевые хранилища:
  -	В реляционную БД (PostgreSQL) – структурированные данные.
  -	В NoSQL-хранилище (MongoDB/JSONB) – неструктурированные данные.

  -	Создать DAG с последовательностью задач:

  -	Добавить обработку ошибок и логирование.
4.	Настройка Data Lineage (OpenMetadata):
  -	Настроить отслеживание происхождения данных.
5.	Использование генеративного ИИ для проверки кода:
  -	Провести проверку кода ETL-процессов с использованием генеративного ИИ.
  -	Исправить выявленные ошибки.
  -	Отразить результаты проверки в отчете.

Результат:
  -	Код Spark-приложений для трансформации.
  -	DAG для Airflow.
  -	Скриншоты интерфейса OpenMetadata с Data Lineage.

### Часто задаваемые вопросы

Вопрос: Что делать, если данные слишком большие для локального компьютера?

  Ответ: Используйте усеченный датасет (sample) для разработки и отладки. Полный датасет можно обрабатывать на облачной платформе (Yandex Cloud, AWS) или демонстрировать на защите с помощью скриншотов.

Вопрос: У нас нет данных для разметки. Можно ли пропустить этот этап?

  Ответ: Если в вашей задаче разметка не требуется (например, прогнозирование временных рядов или биржевые данные), этот этап можно пропустить с обоснованием в отчете.

  Ответ: Рекомендуемый минимальный объем: 100 000 записей для обработки и 10 000 записей для ML-модели (сбалансированных по классам).

Вопрос: Можно ли использовать облачные сервисы вместо локального развертывания?
  
  Ответ: Да. Это даже приветствуется. Опишите в отчете, какие облачные сервисы использовались и почему.
