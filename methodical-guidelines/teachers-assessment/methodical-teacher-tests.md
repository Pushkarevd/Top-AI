Какие из архитектурных принципов позволяют хранить, обрабатывать и анализировать огромные объемы данных?

Соотнесите характеристику больших данных и технологическое решение для работы с данными:

Как называется технологическое решение, заключающееся в распределении данных между множеством серверов вместо наращивания мощности одного сервера?

**Ответ:** 2 - горизонтальное масштабирование.

**Вопрос 5.**

Соотнесите типы обработки данных классической модели с их направленностью:

**Ответ:**

OLTP -> Ориентирована на быстрое выполнение множества коротких операций от пользователей

OLAP -> Ориентирована на анализ больших массивов данных и построение отчетности

**Вопрос 6.**

Выберите ключевые характеристики ОLTP систем.

**Ответ:** 1 - короткие запросы, большое количество операций в единицу времени; 3 - низкая задержка (постоянное обновление данных); 5 - строгая целостность данных.

**Вопрос 7.**

Выберите ключевые характеристики ОLAP систем.

**Ответ:** 2 - длинные запросы с группировками и агрегациями; 4 - допускается задержка актуализации данных (пакетное обновление); 6 - консистентность на уровне витрин загрузок.

**Вопрос 8.**

Распределите примеры систем по типу обработки данных.

**Ответ:** OLAP – BI-отчетность; аналитика по событиям; OLTP – заказ в маркетплейсе; система учета на предприятии.

**Вопрос 9.**

Какие ограничения имеют реляционные СУБД для хранения, обработки и анализа больших данных?

**Ответ:** 1 - Невозможность горизонтального роста системы и очень дорогой вертикальный рост; 2 - Структура данных не предполагает работу с разнородными данными в одной логической структуре; 3 - Очень медленная обработка на больших потоках входящих данных; 4 - Строчное хранение данных не эффективно для аналитических запросов.

**Вопрос 10.**

Что включает в себя типовая архитектура распределенной системы данных.

**Ответ:** 1 - Узлы хранения; 2 - Управляющий слой; 3 - Слой метаданных; 4 - Сетевой доступ к данным; 5 - Механизмы отказоустойчивости; 6 - Пользовательские приложения и API (front-end сервиса).

Какие логические модели хранения данных используются для больших данных?

Соотнесите тип NoSQL базы данных со способом организации данных.

**Ответ:**

Графовые БД -> Данные хранятся в виде узлов (сущностей) и ребер (связей между ними)

БД «Ключ-значение» -> Данные представляют собой массив пар, где уникальный ключ указывает на определенное значение

документные БД -> Данные хранятся в виде документов, каждый из которых имеет свою структуру

**Вопрос 3.**

Соотнесите для каких случаев какой тип хранения является предпочтительным.

**Ответ:**

Графовые БД -> Поиск скрытых взаимосвязей в сложных сетях

Колоночные БД -> Анализ огромных массивов информации и построение аналитических отчетов в реальном времени

БД «Ключ-значение» -> Наиболее простой вариант хранилища данных, ориентированный на максимальную скорость работы, экстремальные нагрузки и простоту структуры данных

документные БД -> Гибкое хранение быстро меняющихся данных о сессиях пользователей

**Вопрос 4.**

Какими основными особенностями обладает хранилище данных DWH?

**Ответ:** 1- данные организованы вокруг ключевых бизнес-понятий, а не вокруг процессов обычных приложений; 3 - информация из разрозненных систем приводится к единым стандартам; 4 - данные не удаляются и не перезаписываются при изменении; 5 - данные загружаются батчами или потоком.

**Вопрос 5.**

Определите о какой архитектурной концепции сказано далее: «Централизованный подход, где сначала создается единое гигантское детализированное хранилище данных в нормализованной форме (3NF), а затем из него выделяются тематические витрины данных для конкретных отделов».

**Ответ:** 3 - Архитектура Ральфа Кимбалла (подход «снизу вверх»).

**Вопрос 6.**

Определите о какой архитектурной концепции сказано далее: «Хранилище собирается из отдельных тематических витрин, которые объединены между собой общими справочниками. Данные хранятся в денормализованном виде по схеме «звезда» или «снежинка»».

**Ответ:** 2 - Архитектура Билла Инмона (подход «сверху вниз»)

**Вопрос 7.**

Соотнесите инфраструктурные архитектуры с их описанием:

**Ответ:**

Классическое DWH -> Хранилище разворачивается на собственных серверах компании. Дает полный контроль над безопасностью, но требует больших финансовых затрат и затрат на администрирование

Лямбда - архитектура -> Поток данных разделяется на 2 пути: быстрый для обработки данных в реальном времени и медленный для глубокого пакетного анализа исторических данных

Облачные DWH -> Полностью управляемые облачные аналитические платформы. Вычислительные мощности масштабируются отдельно от объема хранения

Каппа - архитектура -> Упрощение Лямбда-архитектуры, где и исторические и потоковые данные обрабатываются через один и тот же конвейер обработки логов 

**Вопрос 8.**

Какие технологии масштабирования РСУБД существуют?

**Ответ:** 1 - Вертикальное масштабирование; 2 - Репликация; 3 – Шардирование.

**Вопрос 9.**

Соотнесите виды облачных хранилищ и их описание.

**Ответ:**

Публичные облака -> Размещены внутри организации или в дата центре стороннего провайдера, но доступ к ним только у сотрудников и внутренних пользователей

Частные облака -> Аренда необходимого объема хранилища у сторонней организации

Гибридные облака -> Комбинация двух других решений

**Вопрос 10.**

Какими главными отличиями от других хранилищ данных обладают сети хранения данных?

**Ответ:** 1 - блочный доступ – сервер сам создает на диске файловую систему, работа идет с кусками данных.

Выберите утверждения относящиеся к ELT консолидации.

Выберите основные типы разнородностей при интеграции данных.

Выстройте обобщенную схему процесса консолидации данных в соответствии с порядком шагов.

Шаг 1 -> Извлечение данных из разнородных источников

Шаг 2 -> Очистка и валидация данных

Какие из преимуществ и недостатков относятся к архитектурной модели управления данными ETL.

Шаг 5 -> Обогащение данных - добавление контекста для удобства будущей аналитики

Шаг 6 -> Маскирование и безопасность – защита персональных и конфиденциальных данных

### Блок 1. Распределённые системы и MPP-архитектуры

**Вопрос 1**

Что такое MPP-система (Massively Parallel Processing)?

**Ответ:** B) Архитектура распределённой обработки, в которой каждый узел независимо обрабатывает свою часть данных без общего хранилища

**Вопрос 2**

Какие характеристики относятся к архитектуре Shared-Nothing, используемой в MPP-системах?

**Ответ:** A) - Каждый узел имеет собственную память и дисковое хранилище; C) - Узлы обмениваются данными по сети; D) - Отсутствие единой точки отказа (при правильной реализации).

**Вопрос 3**

Какое из утверждений о сравнении MPP и MapReduce является верным?

**Ответ:** C) MapReduce ориентирован на пакетную обработку с записью промежуточных результатов на диск, а MPP — на выполнение сложных аналитических запросов в памяти

### Блок 2. Распределённая файловая система HDFS

**Вопрос 4**

Какую роль выполняет NameNode в архитектуре HDFS?

**Ответ:** B) Хранит метаданные файловой системы (дерево каталогов, соответствие блоков файлам, расположение реплик)

**Вопрос 5**

Что такое heartbeat в контексте HDFS?

**Ответ:** B) – Периодический сигнал от DataNode к NameNode о своей работоспособности

**Вопрос 6**

Какой коэффициент репликации по умолчанию используется в HDFS?

**Ответ:** C) – 3

**Вопрос 7**

Какие из утверждений о HDFS являются верными?

**Ответ:** A) – HDFS оптимизирована для режима «записать один раз, читать много раз»; C) – HDFS обеспечивает отказоустойчивость за счёт репликации блоков; D) – HDFS хранит данные в виде блоков фиксированного размера (по умолчанию 128 МБ).

**Вопрос 8** 

Какая команда HDFS-клиента используется для загрузки локального файла в распределённое хранилище?

**Ответ:** B) – hdfs dfs -put

### Блок 3. Менеджер ресурсов YARN

**Вопрос 9**

Какие компоненты входят в архитектуру Apache YARN и какие роли они выполняют?

**Ответ:** 

A) – ResourceManager — глобальный арбитр ресурсов кластера

B) – NodeManager — агент на каждом узле, управляющий контейнерами

C) – ApplicationMaster — компонент, отвечающий за конкретное приложение(например, Spark-приложение)

### Блок 4. Фреймворк Apache Spark

**Вопрос 10**

Что такое RDD (Resilient Distributed Dataset) в Apache Spark?

**Ответ:** B) – Устойчивый распределённый набор данных — фундаментальная абстракция Spark для работы с данными.

**Вопрос 11**

Что такое ленивые вычисления (lazy evaluation) в Apache Spark?

**Ответ:** B) – Отложенное выполнение трансформаций до момента вызова действия (action)

**Вопрос 12**

Что такое DAG (Directed Acyclic Graph) в контексте Apache Spark?

**Ответ:** B) – Ориентированный ациклический граф, представляющий последовательность вычислений

**Вопрос 13**

Какие из перечисленных операций в Apache Spark являются трансформациями (transformations)?

**Ответ:** A) map(); B) filter(); D) join()

**Вопрос 14**

Какие из перечисленных операций в Apache Spark являются действиями (actions)?

**Ответ:** B) count(); C) collect(); E) show()

**Вопрос 15 **

Какой компонент Spark-приложения координирует выполнение и хранит контекст приложения?

**Ответ:** C) Driver

**Вопрос 16**

Какие модели запуска Spark-приложений поддерживаются?

**Ответ:** A) YARN; B) Kubernetes; C) Standalone; D) Local

### Блок 5. Apache Trino

**Вопрос 17**

Для чего предназначен Apache Trino (бывший PrestoSQL) в архитектуре Lakehouse?

**Ответ:** B) Для распределённого выполнения интерактивных аналитических SQL-запросов с низкой задержкой

**Вопрос 18 (одиночный выбор)**

Какое ключевое отличие Apache Trino от Apache Spark SQL?

**Ответ:** B) Trino оптимизирован на время отклика (latency) для интерактивных SQL-запросов, а Spark SQL — на пропускную способность для сложной обработки данных

**Вопрос 19**

Какие утверждения о связке Spark + Trino + Apache Iceberg являются верными?
**Ответ:** A) Spark используется для тяжёлой обработки и записи данных в Iceberg-таблицы; B) Trino используется для интерактивного чтения и анализа тех же Iceberg-таблиц; D) Iceberg обеспечивает единый табличный формат, доступный обоим движкам без конвертации

**Вопрос 20**

Какие преимущества даёт использование Trino для аналитических запросов к Iceberg-таблицам?

**Ответ:** A) Возможность выполнять SQL-запросы без запуска JVM-контейнеров Spark; B) Мгновенный доступ к первым строкам результата (низкая латентность); C) Подключение из BI-систем (Tableau, Superset, DBeaver) через стандартный SQL-интерфейс; E) Использование скрытого партиционирования Iceberg для оптимизации чтения.

### Блок 6. Apache Iceberg и архитектура Data Lake

**Вопрос 21**

Зачем при создании Iceberg-таблицы в лабораторных работах явно указывается format-version='2'?

**Ответ:** B) Для поддержки файлов удалений (delete files) и операций обновления на уровне строк (row-level updates), что необходимо для инкрементальной (потоковой) записи данных

**Вопрос 22**
Какие преимущества Apache Iceberg имеет перед обычными Parquet-файлами в HDFS?

**Ответ:** A) Поддержка ACID-транзакций; B) Схемная эволюция (добавление, удаление, переименование колонок без переписывания данных); C) Time Travel — доступ к историческим снимкам данных; D) Скрытое партиционирование с автоматическим управлением физическим размещением файлов.

**Вопрос 23**

Что такое скрытое партиционирование (hidden partitioning) в Apache Iceberg?

**Ответ:** B) Механизм, при котором Iceberg сам управляет физическим размещением файлов на основе логической стратегии, заданной пользователем

**Вопрос 24**

Какие возможности Apache Iceberg поддерживают развитие хранилища данных в рамках архитектуры Lakehouse?

**Ответ:** A) Совместное чтение одних и тех же данных из Spark, Trino, Flink без конвертации; B) Инкрементальная запись данных (streaming) при использовании format-version='2'; C) Откат к предыдущим версиям данных (rollback); E) Поддержка схемной эволюции без переписывания всех данных.

**Вопрос 25 (одиночный выбор)**

Что такое Lakehouse-архитектура?

**Ответ:** B) Архитектура, сочетающая преимущества Data Lake (масштабируемость, гибкость) и Data Warehouse (ACID-транзакции, управление схемой).

Соотнесите показатель качества данных (DQ) с его описанием:

**Ответ:**

Полнота -> Характеризует наличие всех необходимых данных

Корректность -> Характеризует соответствие данных заданному формату, правилам и бизнес-схеме

Точность -> Характеризует степень соответствия данных реальности

Уникальность -> Характеризует отсутствие дубликатов и повторных записей в данных

Согласованность -> Характеризует отсутствие противоречий данных при анализе логических связей внутри одного датасета

Актуальность -> Характеризует временную ценность данных

**Вопрос 2.**

Инженер данных обнаружил, что в таблице orders (заказы) в столбце delivery_date (дата доставки) у 5% строк стоит значение NULL, хотя по бизнес-логике товар не может быть заказан без указания даты доставки. Какой показатель качества данных (DQ) нарушен?

**Ответ:** 2 - Полнота (Completeness) 

**Вопрос 3.**

В аналитическое хранилище из двух разных CRM-систем загружаются профили клиентов. В первой системе формат записи телефона +7 (999) 111-22-33, а во второй — 89991112233. Какая метрика качества данных страдает в первую очередь до этапа трансформации?
**Ответ:** 2 - Согласованность / Консистентность (Consistency) 

**Вопрос 4.**

Метрика «Своевременность / Актуальность» (Timeliness) в ELT-архитектуре обычно измеряется как:

**Ответ:** 1 - Разница во времени между моментом генерации события в источнике и моментом его доступности для аналитического запроса в DWH. 

**Вопрос 5.**

Какие из перечисленных проверок DQ (Data Quality) можно эффективно выполнять «на лету» в процессе стриминга данных (например, внутри Apache Kafka / Flink), не дожидаясь загрузки в DWH? (Выберите ВСЕ верные варианты)

**Ответ:** 1 - Проверка структуры JSON на соответствие схеме (Schema Validation); 2 - Проверка на наличие пустых значений (NOT NULL) в обязательных полях; 4 - Проверка соответствия типов данных (например, что в поле price пришло число, а не текст).

**Вопрос 6.**

На каком этапе пайплайна проверка качества данных встраивается в ETL архитектуру?

**Ответ:** 1 - Качество данных проверяется до загрузки в базу.

**Вопрос 7.**

На каком этапе пайплайна проверка качества данных встраивается в ELT архитектуру?

**Ответ:** 2 - Проверки DQ пишутся на SQL и запускаются асинхронно после загрузки данных в хранилище.

**Вопрос 8.**

Какие из утверждений относительно оркестрации конвейеров данных являются верными?

**Ответ:** 1 - Это процесс автоматического управления, координации и мониторинга последовательности шагов (задач) по обработке данных в рамках ETL/ELT процессов; 2 - В основе лежит концепция DAG направленного ацикличного графа, где узлами являются задачи, а ребрами – зависимости между ними.

**Вопрос 9.**

Соотнесите ключевые функции оркестратора с их содержанием.

**Ответ:**

Управление зависимостями -> Гарантирует строгий порядок выполнения

Планирование -> Запуск пайплайнов по расписанию, по событию или через API-триггер

Мониторинг и логирование -> Наличие UI-панели (дашборда), где в реальном времени видно статус каждой задачи (Успешно, Ошибка, В процессе) и доступны детальные логи выполнения для отладки

Обработка ошибок и отказоустойчивость -> Повторные попытки перезапуска задачи и оповещение инженеров об окончательном падении задачи

**Вопрос 10.**

Какие функции выполняет платформа управления данными Open Metadata в разрезе проблемы Data Swamp?

**Ответ:** 1- Анализ влияния изменений; 2 - Отладка ошибок; 3 - Обнаружение мусора.
