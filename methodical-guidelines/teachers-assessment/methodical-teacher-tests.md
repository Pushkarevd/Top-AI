## Модуль 1. Занятие 1.1.
(индикатор BD-3.1, уровень Б)

**Вопрос 1.**
Какие характеристики данных относятся к Big Data?
**Ответ:** 1 - физический размер данных, превышающий возможности одного сервера; 2 - высокий темп поступления информации для обработки; 3 - разнообразие форматов представления;4 - качество и точность данных; 5 - польза от извлеченной информации.

**Вопрос 2.**
Какие из архитектурных принципов позволяют хранить, обрабатывать и анализировать огромные объемы данных?
**Ответ:** 1 - Горизонтальное масштабирование данных; 2 - Распределенное хранение данных; 3 - Перенос процесса вычислений к данным; 4 - Выделение OLTP и OLAP контуров; 5 - Параллельная и пакетная обработка данных; 6 - Репликация данных; 7 - Резервирование вычислений и повтор задач; 8 - Контрольные точки.

**Вопрос 3.**
Соотнесите характеристику больших данных и технологическое решение для работы с данными:
**Ответ:**
Volume -> Распределенные файловые системы (HDFS, S3)
Velocity -> Потоковая обработка (Kafka, Spark Streaming)
Variety -> NoSQL базы данных, Data Lake архитектуры
Value -> Продвинутая аналитика, AI/ML платформы
Veracity -> Системы очистки данных, ML алгоритмы

**Вопрос 4.**
Как называется технологическое решение, заключающееся в распределении данных между множеством серверов вместо наращивания мощности одного сервера?
**Ответ:** 2 - горизонтальное масштабирование.

**Вопрос 5.**
Соотнесите типы обработки данных классической модели с их направленностью:
**Ответ:**
OLTP -> Ориентирована на быстрое выполнение множества коротких операций от пользователей
OLAP -> Ориентирована на анализ больших массивов данных и построение отчетности

**Вопрос 6.**
Выберите ключевые характеристики ОLTP систем.
**Ответ:** 1 - короткие запросы, большое количество операций в единицу времени; 3 - низкая задержка (постоянное обновление данных); 5 - строгая целостность данных.

**Вопрос 7.**
Выберите ключевые характеристики ОLAP систем.
**Ответ:** 2 - длинные запросы с группировками и агрегациями; 4 - допускается задержка актуализации данных (пакетное обновление); 6 - консистентность на уровне витрин загрузок.

**Вопрос 8.**
Распределите примеры систем по типу обработки данных.
**Ответ:** OLAP – BI-отчетность; аналитика по событиям; OLTP – заказ в маркетплейсе; система учета на предприятии.

**Вопрос 9.**
Какие ограничения имеют реляционные СУБД для хранения, обработки и анализа больших данных?
**Ответ:** 1 - Невозможность горизонтального роста системы и очень дорогой вертикальный рост; 2 - Структура данных не предполагает работу с разнородными данными в одной логической структуре; 3 - Очень медленная обработка на больших потоках входящих данных; 4 - Строчное хранение данных не эффективно для аналитических запросов.

**Вопрос 10.**
Что включает в себя типовая архитектура распределенной системы данных.
**Ответ:** 1 - Узлы хранения; 2 - Управляющий слой; 3 - Слой метаданных; 4 - Сетевой доступ к данным; 5 - Механизмы отказоустойчивости; 6 - Пользовательские приложения и API (front-end сервиса).
 

## Модуль 1. Занятие 1.2.
(индикатор BD-3.1, уровень С)

**Вопрос 1.**
Какие логические модели хранения данных используются для больших данных?
**Ответ:** 2 - документные БД; 3- БД «Ключ-значение»; 4- Колоночные БД; 5 - Графовые БД.

**Вопрос 2.**
Соотнесите тип NoSQL базы данных со способом организации данных.
**Ответ:**
Графовые БД -> Данные хранятся в виде узлов (сущностей) и ребер (связей между ними) 
Колоночные БД -> Данные физически записываются и хранятся на диске по динамическим колонкам 
БД «Ключ-значение» -> Данные представляют собой массив пар, где уникальный ключ указывает на определенное значение
документные БД -> Данные хранятся в виде документов, каждый из которых имеет свою структуру

**Вопрос 3.**
Соотнесите для каких случаев какой тип хранения является предпочтительным.
**Ответ:**
Графовые БД -> Поиск скрытых взаимосвязей в сложных сетях
Колоночные БД -> Анализ огромных массивов информации и построение аналитических отчетов в реальном времени
БД «Ключ-значение» -> Наиболее простой вариант хранилища данных, ориентированный на максимальную скорость работы, экстремальные нагрузки и простоту структуры данных
документные БД -> Гибкое хранение быстро меняющихся данных о сессиях пользователей

**Вопрос 4.**
Какими основными особенностями обладает хранилище данных DWH?
**Ответ:** 1- данные организованы вокруг ключевых бизнес-понятий, а не вокруг процессов обычных приложений; 3 - информация из разрозненных систем приводится к единым стандартам; 4 - данные не удаляются и не перезаписываются при изменении; 5 - данные загружаются батчами или потоком.

**Вопрос 5.**
Определите о какой архитектурной концепции сказано далее: «Централизованный подход, где сначала создается единое гигантское детализированное хранилище данных в нормализованной форме (3NF), а затем из него выделяются тематические витрины данных для конкретных отделов».
**Ответ:** 3 - Архитектура Ральфа Кимбалла (подход «снизу вверх»).

**Вопрос 6.**
Определите о какой архитектурной концепции сказано далее: «Хранилище собирается из отдельных тематических витрин, которые объединены между собой общими справочниками. Данные хранятся в денормализованном виде по схеме «звезда» или «снежинка»».
**Ответ:** 2 - Архитектура Билла Инмона (подход «сверху вниз»)

**Вопрос 7.**
Соотнесите инфраструктурные архитектуры с их описанием:
**Ответ:**
Классическое DWH -> Хранилище разворачивается на собственных серверах компании. Дает полный контроль над безопасностью, но требует больших финансовых затрат и затрат на администрирование
Лямбда - архитектура -> Поток данных разделяется на 2 пути: быстрый для обработки данных в реальном времени и медленный для глубокого пакетного анализа исторических данных
Облачные DWH -> Полностью управляемые облачные аналитические платформы. Вычислительные мощности масштабируются отдельно от объема хранения
Каппа - архитектура -> Упрощение Лямбда-архитектуры, где и исторические и потоковые данные обрабатываются через один и тот же конвейер обработки логов 

**Вопрос 8.**
Какие технологии масштабирования РСУБД существуют?
**Ответ:** 1 - Вертикальное масштабирование; 2 - Репликация; 3 – Шардирование.

**Вопрос 9.**
Соотнесите виды облачных хранилищ и их описание.
**Ответ:**
Публичные облака -> Размещены внутри организации или в дата центре стороннего провайдера, но доступ к ним только у сотрудников и внутренних пользователей
Частные облака -> Аренда необходимого объема хранилища у сторонней организации
Гибридные облака -> Комбинация двух других решений

**Вопрос 10.**
Какими главными отличиями от других хранилищ данных обладают сети хранения данных?
**Ответ:** 1 - блочный доступ – сервер сам создает на диске файловую систему, работа идет с кусками данных.
